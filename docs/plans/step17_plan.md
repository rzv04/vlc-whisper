# Step 17 Plan: Seeking & Discontinuity support

## Goal
When playback seeks or jumps (user seek bar, stream discontinuity, rate change), the plugin
seamlessly re-syncs captions: clear the current OSD overlay, tear down the session with
`STOP` (`SEEK_DISCONTINUITY`), discard stale queued audio, and start a fresh session epoch —
without interrupting VLC playback. No pre-seek audio leaks into the post-seek transcription.

  SEEK_DISCONTINUITY, reset SPSC/VAD, new epoch), `docs/decisions.md:43` (same policy, ADR

- **VLC/worker/protocol version affected**: VLC 3.0.23 (vendored headers). Protocol change:
  none — `STOP` and re-`START` already exist on the wire; `SEEK_DISCONTINUITY=2` reason is
  documented but has no constant yet.
- **Assumptions and explicit non-goals**:
  - Detection signal is `BLOCK_FLAG_DISCONTINUITY` (0x0001, `vlc_block.h`) on the audio block
    in `vw_plugin_filter`, with a non-monotonic-PTS fallback (backward jump vs
    `sys->capture.last_pts_us`). Both are read in the realtime callback — the callback only
    sets atomics; all teardown/restart runs on the sender thread (Rule 4).
  - `timeline_origin_pts_us` is transmitted but the worker does not read it today (verified by
    grep); the plan passes the post-seek PTS anchor through it for forward-compat, but the real
    re-sync is the new `session_id` (regenerated by `start_session`) + worker `STOP`/`START`
    cycle, which already exists.
  - Out of scope: session-ID validation on received segments (roadmap 17d), SPU flush (17b),
    source-decode seek engine (17c/17d), `is_seeking` repositioning, MF lifecycle. Media swap =
    new filter instance, handled by open/close lifecycle, not here.
  - Postmortem note: a segment hypothesis left in the worker builder at seek time would be
    stamped with the NEW session_id and rendered post-seek — the worker must discard the builder
    on `START` (see Design).

## Scope
- **In scope**:
  - Plugin: detect discontinuity in `vw_plugin_filter` (flag + PTS fallback), set an atomic
    `discontinuity_pending` + record the new PTS anchor; sender loop reacts (clear presenter,
    `stop_session(SEEK_DISCONTINUITY)`, drain-discard SPSC, `start_session(new anchor)`).
  - Protocol: `VW_CTRL_REASON_SEEK_DISCONTINUITY 2U` constant (the only STOP reason this step
    needs; `USER_STOP`/`MEDIA_END` stay documented-only).
  - Worker: discard segment-builder content on `START` (drain-pop, reusing existing ownership),
    so no pre-seek hypothesis crosses the epoch boundary. `audio_buf` clearing on `STOP` already
    exists; VAD is stateless (energy check) so no VAD reset is needed.
  - Docs: roadmap 17 → `[x]`, architecture seek row (already correct; add shipped note),
    api-contracts STOP reason constant, test-strategy entry; fix `vlc-api-essentials.md`'s
    `vw_spsc_queue_reset()` reference (the API does not exist — the design uses drain-discard
    via `vw_spsc_queue_pop`, matching the pause path).
- **Out of scope**: everything listed in assumptions (17b/c/d), GPU, quality.
- **Files/components expected to change**:
  - `plugin/src/vw_whisper_module.c` (callback detection + sender reaction)
  - `protocol/include/vw_protocol_types.h` (reason constant)
  - `worker/src/vw_worker.c` (builder discard on START)
  - `tests/unit/vw_test_worker_client.c` (STOP reason assert), `tests/integration/test_worker_lifecycle.c`
    (STOP→START restart on one connection)
  - `docs/roadmap.md`, `docs/api-contracts.md`, `docs/architecture.md`, `docs/test-strategy.md`,
    `docs/vlc-api-essentials.md`

## Design
- **Inputs and outputs**: audio block flags/PTS (callback) → atomic flag + anchor (sender loop)
  → `STOP`/`START` frames → worker new session_id + empty builder → clean post-seek captions.
- **Ownership/threading model**: callback (audio thread) writes two atomics only —
  `_Atomic bool discontinuity_pending` and `_Atomic int64_t resume_pts_us` — never IPC/heap/
  locks (Rule 4). Sender loop checks the flag once per iteration (same cadence as the pause
  poll; no extra throttle needed — it reuses the existing per-iteration check). Restart sequence
  runs on the sender thread: clear presenter → `stop_session(SEEK_DISCONTINUITY)` →
  `while (vw_spsc_queue_pop) discard` → `start_session(resume_pts_us)` → clear flag. The
  worker's existing `session_id` gating on `AUDIO` is the backstop: any in-flight pre-seek chunk
  that slips past the drain is dropped at the worker after the restart.
- **Bounds, time units, and failure behavior**: `start_session` may block up to 5 s waiting for
  `STARTED` (existing behavior, same as initial start); the SPSC queue caps at ~8 s and drops
  newest meanwhile. Failure paths reuse existing fail-closed behavior: `stop_session`/`start_session`
  drop the transport on write failure → sender marks worker dead → passthrough; playback never
  affected. A seek while paused restarts the session too (audio discarded while paused anyway).
- **Privacy/security implications**: none (local IPC only).
- **Protocol change**: none (reason constant only; wire values unchanged).

## Acceptance criteria
- [ ] Seek during playback: OSD captions clear immediately; new captions resume ~8s later from
      the new position (batch-window latency, by design); no caption mixes pre-seek and post-seek
      audio.
- [ ] `PLUGIN_DISCONTINUITY` / `PLUGIN_SESSION_RESTART` log lines appear on seek; worker logs
      `WORKER_SESSION stopped` then `session started (STARTED sent)` with a new session.
- [ ] Pre-seek audio never reaches the post-seek window (verified by the worker builder discard +
      session_id gating).
- [ ] Seek while paused, rapid seeks, seek at EOF/media end: no transport drop, no crash,
      playback unaffected.
- [ ] Automated tests cover the STOP-reason constant and the STOP→START restart path; docs
      updated.

## Test plan
- Automated gate (AGENTS.md rule 10): `clang-format --dry-run --Werror` on touched files;
  `cmake --preset linux-x64-debug && cmake --build --preset linux-x64-debug && ctest
  --preset linux-x64-debug`; `ctest --test-dir build/linux-x64-debug -T memcheck`;
  Windows cross-build (`windows-x64-debug` preset).
- Unit: `vw_test_worker_client` — extend the fake server to decode the `STOP` payload and assert
  `reason == VW_CTRL_REASON_SEEK_DISCONTINUITY` for a seek-flavored stop.
- Integration: `test_worker_lifecycle` — on one connection: START → AUDIO → STOP
  (SEEK_DISCONTINUITY) → START again (new session_id) → AUDIO → STOP → SHUTDOWN → exit 0,
  proving the worker accepts the restart cycle and drops stale audio.
- Manual acceptance (live VLC, required — the flag detection is module-internal): play video with
  captions, seek mid-speech; captions clear immediately and resume cleanly from the new position;
  verify `PLUGIN_DISCONTINUITY` + restart logs.
