# Implementation Roadmap

This document outlines the ordered sequence of deliverables for building `vlc-whisper`. Each milestone must pass its specified exit status before proceeding to the next.

---

## Milestone 0: Core protocol & worker scaffold (Complete)

- [x] 1. Pin external dependencies: `whisper.cpp` (C API), VLC 3.0 headers (`vlc_common.h`, `vlc_filter.h`), and C test runner.
- [x] 2. Establish C17 build system (`CMakeLists.txt`), strict warning flags, clang-format rules, and memory leak checks (Valgrind/ASan).
- [x] 3. Define binary IPC protocol frames: `HELLO`, `HELLO_ACK`, `START`, `STARTED`, `AUDIO`, `SEGMENT`, `STOP`, `PAUSE`, `RESUME`, `SHUTDOWN`, `STATUS`, `ERROR`.
- [x] 4. Implement protocol codec & validation: endianness, magic bytes (`VLCW`), payload size bounds, UTF-8 checks.
- [x] 5. Implement thread-safe SPSC ring buffer for 16 kHz Mono S16LE PCM chunks in C.
- [x] 6. Implement local IPC server (`vlc-whisper-worker` binary) using named pipes (Windows) and Unix domain sockets (Linux) with 32-byte token auth.

**Exit Status:** **DONE** — Protocol test suite passes 100% on Linux and Windows. Clean memory leak check under Valgrind.

## Milestone 5: Quality Corpus, Optional Transcription Pass & Reliability Gate (Planned)

Milestone 5 is intentionally narrow. Before expanding the feature surface, VLC-Whisper must first establish a trustworthy quality baseline, may then perform one corpus-gated transcription-quality pass if the measurements justify it, and must finish with a dedicated bug-hunt/reliability pass. Local-file seeking, live/non-seekable behavior, caption stability, privacy, and playback safety remain regression constraints throughout.

### Phase 1 — Finish the quality corpus

- [ ] 24. **Finish Regression Corpus & Automated Quality/Latency Gates**: complete the small locally downloaded, copyright-safe regression corpus (approximately 20 samples, with at least English and Romanian) without committing media fixtures to the repository. Keep only the downloader/manifest, ground-truth references, metadata, and benchmark tooling under version control. Exercise both offline/source-decoder transcription and the real live/lookahead caption path where applicable. Track per-language WER/CER plus first-caption latency, caption latency percentiles, inference real-time factor, timing error, duplicate/hallucination rate, dropped-audio count, queue high-water marks, translation timing where enabled, and visible caption stability so later changes have a reproducible baseline.

### Phase 2 — Optional transcription quality pass

- [ ] 25. **Optional Measured Transcription Quality Pass**: only if the completed corpus shows worthwhile room for improvement, investigate accuracy, hallucination reduction, punctuation, prompt/context policy, VAD interaction, decoding parameters, long-form behavior, and live/non-seekable latency. LocalAgreement-, AlignAtt-, alternative streaming-policy, right-edge hypothesis, or other scheduling experiments belong here only when they can be compared against the corpus. Adopt a change only when measurements show a net improvement without material regression to seek recovery, local-media latency, live latency, caption stability, or playback safety. This phase may be explicitly skipped when the current measured baseline is judged sufficient; skipping it must not block Milestone 5 completion.

### Phase 3 — Dedicated bug hunt and reliability pass

- [ ] 26. **Final Bug Hunt, Reliability & Release Gate**: after the corpus is finished and the optional quality pass is completed or explicitly skipped, perform a dedicated no-new-features hardening pass before Milestone 6. Hunt regressions across local/lookahead and live/non-seekable media, seek/pause/resume/rate changes, media swaps, translation, model provisioning, CPU/GPU fallback, worker/plugin lifecycle, installer/uninstaller behavior, logging/diagnostics, and failure recovery. Close or explicitly classify known release-blocking defects, run the full native tests and memory checks, validate reproducible release artifacts and clean-machine smoke behavior where available, and improve CI/release automation as needed to make the resulting baseline dependable. Milestone 6 must not begin until this gate is satisfied.

**Exit Status:** **PLANNED** — The local EN/RO regression corpus and benchmark gates are usable and reproducible; the transcription-quality pass is either completed with measured wins or deliberately skipped with the baseline recorded; and a final dedicated bug-hunt/reliability pass finds no known release-blocking regression before feature expansion resumes.

## Milestone 6: Native Settings & Subtitle Hub (Planned)

Milestone 6 is dedicated exclusively to replacing the constrained settings surface with a durable native Qt control center and expanding that control center into VLC-Whisper's subtitle hub. The hub should manage transcription, translation, subtitle files, models, diagnostics, and user-facing automation policies without moving inference or blocking work into VLC's realtime callbacks. Local `whisper.cpp` remains the default transcription path.

- [ ] 27. **Production Native Qt Settings & Subtitle Hub**: replace the Lua settings UI with the validated native Qt frontend while preserving safe apply/restart semantics and the current plugin/worker ownership model. The native hub becomes the user-facing control plane for model/backend/language/thread selection, translation, subtitle workflows, diagnostics, version information, and future optional providers. Bundle all required Qt runtime components so users install no separate Qt packages. Keep the already-hardened worker-owned model downloader during the initial migration; moving the complete provisioning transaction into Qt can be researched later only after settings ownership, process lifetime, locking, and plugin notification are stable.
- [ ] 28. **Expanded Settings & Automation Policies**: introduce clear independent settings for automatic transcription and automatic translation rather than coupling the two. Let users decide whether generated captions start automatically, whether translation starts automatically when eligible, what source/target languages and display mode to use, and how VLC-Whisper behaves when usable subtitles already exist (for example `Prefer existing subtitles`, `Generate if unavailable`, or `Always generate`). Add user-facing latency/quality profiles such as `Low latency`, `Balanced`, and `Accuracy`, plus an `Auto` transcription-language mode that detects from an initial speech-rich sample and locks the result for the session/epoch. Keep advanced algorithm internals out of the stable settings schema unless explicitly exposed as advanced controls.
- [ ] 29. **Canonical Subtitle Document & SRT/WebVTT Import/Export**: define a format-independent timed-cue representation that can hold finalized generated captions, translated captions, imported/downloaded subtitle cues, and later other subtitle sources. Add explicit user-initiated SRT and WebVTT export for source, translated, and optional bilingual output; preserve authentic media cue timestamps rather than presenter reading-floor extensions. Allow SRT/WebVTT import where useful to the hub. Transcript/subtitle persistence remains opt-in and no transcript is written by default.
- [ ] 30. **Full-Media Transcription to Subtitle File**: for seekable media, add an explicit offline/batch workflow that uses the existing source decoder and timing/segmentation stack without playback pacing, producing complete SRT/WebVTT faster than real time where hardware permits. Keep this path isolated from live-caption scheduling so batch throughput work cannot destabilize playback-time transcription.
- [ ] 31. **Existing Subtitle Integration & Translation**: let the hub discover, import, load, and manage suitable existing subtitle files/tracks alongside VLC-Whisper-generated captions. When textual subtitles already exist, allow opt-in translation of those cues without unnecessarily running ASR, while keeping source, translated, downloaded, and generated tracks independently identifiable/selectable and avoiding duplicate on-screen captions. Embedded-track interception may require separate feasibility work; do not weaken the existing generated-caption path to force parity prematurely.
- [ ] 32. **Subtitle Search, Download & Provider Integration**: research and implement a provider-neutral subtitle acquisition layer in the Qt hub, using the functionality of the existing VLSub/OpenSubtitles fork as behavioral reference rather than copying GPL implementation code into the MIT project. OpenSubtitles.com is the initial candidate for hash/name search, preferred-language ranking, quality metadata, download/save/load behavior, and account handling; additional providers remain optional. Use modern HTTPS/networking and protected credential storage where accounts or keys are required.
- [ ] 33. **Automatic/Semi-Automatic Subtitle Synchronization Research**: keep automatic subtitle synchronization as a dedicated research/feasibility item before choosing an implementation. Investigate whether existing subtitles can be aligned with minimal user intervention using approaches such as subtitle-to-subtitle timing references, voice-activity/timing correlation, drift or differing-cut detection, sparse ASR assistance, confidence scoring, or combinations of these. Explore a lightweight confirmation flow in which VLC-Whisper previews a candidate synchronization and asks whether it looks correct; a rejection can drive another candidate or sample. Do not commit the roadmap to a specific VAD algorithm, mathematical model, retry strategy, or automatic-apply threshold until this research is completed and validated on representative media.
- [ ] 34. **Hub UX, Model Management & Diagnostics Completion**: turn the native application into a coherent control center rather than a larger settings dialog. Provide clear current-media/transcription/translation state, model availability and download progress, safe apply/restart feedback, actionable errors, privacy/network disclosures, logs/diagnostics access, export status, and version/update information. Preserve the existing worker/plugin realtime and privacy invariants, and keep full subtitle-authoring/editor scope out of this milestone.

**Exit Status:** **PLANNED** — VLC-Whisper ships a native packaged settings/subtitle hub; automatic transcription and translation are independently controllable; generated and existing subtitles can be managed and translated coherently; SRT/WebVTT import/export and full-media generation are available; subtitle acquisition can be integrated without contaminating the realtime path; and subtitle synchronization has a documented research direction without prematurely locking in an algorithm.

## Milestone 7: Optional Pluggable Inference & BYOK Providers (Planned, Optional)

Local `whisper.cpp` remains the default, offline, no-account transcription backend. This entire milestone is optional and may be deferred indefinitely; completing the core subtitle hub does not require a remote ASR provider, and deferring BYOK must not block VLC ecosystem/compatibility work in Milestone 8.

- [ ] 35. **Provider-Neutral ASR Interface**: if BYOK work is pursued, define a worker-side transcription-provider boundary that normalizes audio/chunk submission and returns caption segments into the existing media-timestamped segment builder/presenter path. Keep provider-specific SDK/HTTP behavior out of VLC callbacks and out of the caption presenter.
- [ ] 36. **ASR Capability Negotiation**: model provider capabilities explicitly, including streaming vs chunked input, segment timestamps, word timestamps, partial hypotheses, language detection, maximum input duration, and cancellation semantics. Providers with weaker timing output must degrade gracefully to coarser segment timing instead of weakening the local Whisper path.
- [ ] 37. **Secure BYOK Credential Persistence**: let users opt into third-party inference by entering their own API key in the native settings application; persist credentials using platform-appropriate protected storage rather than plaintext project configuration wherever feasible, never log keys, never place them in benchmark reports, and redact them from diagnostics.
- [ ] 38. **First Remote Speech Provider Adapter**: implement and validate the first opt-in third-party transcription provider behind the provider interface, including chunk/frame adaptation, cancellation on seek/session changes, rate/error handling, capability-specific timestamp behavior, and regression coverage against local playback semantics.
- [ ] 39. **Provider Privacy & Failure UX**: disclose when audio leaves the device, which provider receives it, what data is sent, and which features/timestamps differ from local Whisper. Remote-provider failure must fail closed to a clear status or an explicitly configured local fallback; it must never silently transmit audio or silently change provider.

**Exit Status:** **OPTIONAL** — If pursued, users can choose local Whisper or an explicitly configured BYOK provider through one capability-aware interface with preserved timeline semantics, secure credential handling, and unambiguous audio-egress disclosure. If deferred, local Whisper and the Milestone 6 subtitle hub remain the complete default product path.

## Milestone 8: VLC Ecosystem & Upstream Compatibility (Planned)

VLC-Whisper should remain useful for VLC 3 users while being prepared to coexist with VLC 4's native speech-to-text work rather than permanently duplicating it. Milestone 7 is optional and does not gate this milestone.

- [ ] 40. **VLC 4 Compatibility Validation**: maintain a VLC 4 validation track as its module/API surface stabilizes; document which VLC-Whisper features work unchanged, require compatibility shims, or are superseded by native functionality, without sacrificing the supported VLC 3 path prematurely.
- [ ] 41. **Native STT Detection & Coexistence Policy**: detect or otherwise account for VLC-native speech-to-text/caption facilities when available so VLC-Whisper does not create duplicate AI subtitle tracks or fight native caption lifecycle behavior. Prefer explicit user choice when both engines are available.
- [ ] 42. **Upstream Contribution Assessment**: identify self-contained work that may benefit VideoLAN independently—such as worker isolation lessons, seek/session epoch handling, source look-ahead behavior, model provisioning hardening, Windows lifecycle fixes, regression tooling, subtitle workflow interoperability, or compatibility findings—and upstream only where the architecture and maintainer interest align.
- [ ] 43. **Platform & Distribution Expansion Based on Demand**: move Linux from a supported build target to a polished native desktop installation path only when packaging/acceptance work is justified, then evaluate macOS and additional Linux packaging formats based on demand. Every newly supported platform must have reproducible artifacts, clean-machine install/upgrade/uninstall coverage, appropriate CI/release automation, and the same realtime-callback, privacy, lifecycle, subtitle-hub, and regression-corpus gates rather than shipping as a best-effort port.

**Exit Status:** **PLANNED** — VLC-Whisper remains a dependable VLC 3 captioning and subtitle-hub solution, has a tested VLC 4 coexistence strategy, and can selectively contribute reusable work upstream without tying the project to duplication of VLC-native STT forever.
